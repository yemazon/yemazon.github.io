01 Real-time AI systems

Token streaming for AI-assisted messaging

Designed an end-to-end path that rendered AI-generated messages incrementally instead of waiting for the complete response, while keeping concurrent streams isolated and observable.

Design decisions

  • Published generation chunks through a real-time event platform.
  • Defined backend decoration APIs and frontend event contracts.
  • Added stream isolation, graceful fallback, and hop-level tracing.

Outcome

Reduced time to first byte from approximately 3.5 seconds to 1.7 seconds and created a reusable path for subsequent messaging workflows.

02 AI quality infrastructure

A reusable LLM evaluation platform

Built an end-to-end LLM-as-a-Judge system for prompt changes, model upgrades, and recurring regression checks, then generalized a use-case-specific workflow into a config-driven platform.

Design decisions

  • Onboarded use cases through YAML, a human-reviewed dataset, and composable evaluators.
  • Combined model-based rubrics with deterministic checks where appropriate.
  • Automated execution, aggregation, HTML reporting, email delivery, and regression alerts.

Validation

Three calibration rounds brought judge-to-human agreement to 87–93% across style, engagement, and personalization.

03 Data systems and diagnostics

Reporting across the full event-to-query path

Reworked a reporting pipeline that turned messaging events into filterable product analytics, and built a diagnostic path for finding records lost across policy filters, joins, and downstream dependencies.

System scope

  • Kafka events and curated intermediate views.
  • Spark aggregation with attribution and account dimensions.
  • Pinot-backed APIs supporting filter-dependent reporting queries.

Operational ownership

Added AI-message attribution and created a stage-by-stage debugger that separated expected policy filtering from event gaps, join loss, storage issues, and burst-induced throttling.

Engineering principles

What I optimize for

01

02
